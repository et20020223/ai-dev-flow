# 第一版設計與驗收

## 已確認需求

- PM 提供大方向，初期用文字和圖片。細節透過 grill-me 方式釐清。
- 以 Vue 前端為主，涵蓋 Nuxt 與 monorepo 內 Node.js；不處理跨 repository 後端協作。
- 視覺接近 Figma，偏差可討論確認。沿用 PR 與人工 code review。
- 需求、方案、成果三個確認點；其他實作細節讓 AI 推進。小 bug 可縮短。
- Codex、Claude Code、Cursor 可接力；支援多人分工與另一個 AI 審查。
- 共用知識放 Git；初始化一次，簡單指令與自然語言使用。
- 不自動 commit、push、開 PR、合併。任務完成時更新 checkpoint。

## 設計取捨

核心使用 Markdown，不依賴某個供應商的 session 格式或工具 API。各入口只路由，共用正文放 WORKFLOW.md，避免三套指令漂移。

每項需求先只建立一份 TASK.md，涵蓋驗收、方案、子任務與交接，降低維護成本。分工以不同檔案範圍和 branch/worktree 為單位；大型功能超過一份紀錄易讀範圍時，拆成互相連結的 task，而非無限擴充同一表格。

grill-me 的分輪問題方法內建在 discover，無原版 Skill tool 依賴，適合不同工具。這是經改寫的整合，不是原版插件的自動安裝；原版可以另外使用，但最終決策需保存到 TASK.md。

安裝器不用 npm dependency；使用 SHA-256 判斷可否覆蓋管理內容。衝突預檢全部完成後才寫檔，各檔案透過暫存檔 rename 寫入。這不是整個目錄的交易式更新，斷電或權限錯誤仍可能中斷；重跑前用 Git diff 檢查。installer 不支援並行執行。

## 驗收矩陣

| ID | 要求 | 驗證方式與狀態 |
| --- | --- | --- |
| F-01 | 三種工具讀同一流程 | 三個入口內容路由至同一路徑；真實 session 接力待試跑 |
| F-02 | 安裝簡單 | 一行 node 指令；無網路或第三方套件；CLI 測試 |
| F-03 | 保留既有設定 | 初始化／更新／重跑及衝突拒絕測試 |
| F-04 | 任務與專案紀錄不被更新覆蓋 | CLI 保留測試 |
| F-05 | 可接續／分工／審查 | 共用流程與任務欄位、範例；真實多人協作待試跑 |
| F-06 | 需求和方案人工確認 | 流程明文與確認欄位；不宣稱技術強制 |
| F-07 | 圖片與 Git 交接完整 | 明確保存、同步和 dirty tree 核對規則 |
| F-08 | 支援新產品／功能／bug | 共用流程依工作型態分流、bug 快速路徑 |

## 第一個真實試跑

在你指定的小型 Vue/Nuxt 專案初始化，提供一個小功能：用第一個工具釐清到方案確認，實作一個子任務後交接；第二個工具必須只靠檔案說出已確認範圍、實際修改、未驗證項目與下一步。核對正確後接續，第三個工具對相同 diff 做審查，最後你驗收。紀錄工具版本、是否自動讀取入口和需要的 fallback，修正一次實際遇到的問題。
